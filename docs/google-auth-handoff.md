# Predare: conectarea cu Google pe asmm.ro

## Stare la 5 octombrie 2026

- Clientul OAuth Web `ASMM - Clerk Production` există în proiectul Google `ASMM Google Authentication`. Originea este `https://asmm.ro`, iar redirectul este `https://clerk.asmm.ro/v1/oauth_callback`. Client ID și Client Secret sunt salvate în Clerk Production, fără a fi copiate în proiect sau Vercel. Conexiunea Google din Clerk Production rămâne dezactivată.
- Paginile de conectare afișează butonul Google numai când `NEXT_PUBLIC_GOOGLE_AUTH_ENABLED=true` este setat la build. Fără variabilă, butonul rămâne ascuns. Comanda locală `dev:staging` îl activează exclusiv pentru testarea cu cheile Clerk Development. Pentru lansarea pe Vercel, setați variabila numai după aprobarea paginilor juridice, publicarea aplicației Google și verificarea conexiunii Clerk, apoi redeploy.
- Brandingul Google folosește `welcome.asmm@gmail.com` ca adresă de asistență. Proiectul este `External` și `Testing`, cu această adresă ca unic tester. Google nu permite încă `Publish app`: lipsesc linkurile publice către politica de confidențialitate și termeni.
- Cele două pagini juridice există numai ca drafturi locale, marcate `noindex` și explicit neaprobate. Nu se publică și nu se introduc în Google până când conducerea sau un jurist confirmă identitatea juridică, sediul, condițiile pentru minori, anulările/rambursările, păstrarea datelor și folosirea analiticelor. Aceste date nu erau disponibile la 5 octombrie.
- Mediul local de test folosește Clerk Development și Atlas Staging. Adresa permisă în Atlas este acum doar IP-ul curent `/32`; conexiunea la `asmm_staging` reușește, iar accesul la `admin` este refuzat. La schimbarea IP-ului, regula trebuie actualizată din nou.
- Un cont Google nou a completat profilul și a ajuns la dashboard. Baza separată conține două profiluri complete, ambele asociate celor două conturi din Clerk Development, cu rol obișnuit și niciun bilet emis. La o încercare de reconectare, utilizatorul a raportat că i se cere profilul din nou, în timp ce jurnalul serverului arată și o redirecționare recentă de la `/auth/complete-profile` la `/dashboard`. Trebuie clarificate contul/sesiunea și URL-ul exact înainte de a considera testul trecut. Legarea unui cont creat inițial prin email nu este încă verificată.
- `npm run test:security` și `npm run test:payments` au trecut, câte 17 teste; `npm run typecheck`, `npm run security:secrets`, lint și `npm run build:isolated` trec. Lint păstrează șase avertismente existente. Scanarea npm raportează vulnerabilități în instrumentele de build/dezvoltare, inclusiv `braces` din Tailwind 3, pentru care la această dată nu există versiune corectată; nu se rulează `npm audit fix --force`, care ar schimba major Tailwind.

**Rămâne de făcut:** confirmarea reutilizării contului existent în browser normal și verificarea legării cu un cont creat inițial prin email; [revizuirea informațiilor juridice](google-auth-legal-review.md) și publicarea paginilor pe `asmm.ro`; completarea linkurilor în Google Branding; trecerea Google în `In production` și orice verificare solicitată; publicarea controlată a codului; testul pe site-ul public; apoi activarea conexiunii și blocarea adreselor alias în Clerk. Codul local de autentificare nu este confirmat ca publicat în Vercel Production. Preview-ul Vercel nu este încă izolat de baza de producție, deci testele cu date de probă rămân locale.
Referințe: [Clerk: conectarea cu Google](https://clerk.com/docs/guides/configure/auth-strategies/social-connections/google), [Google: branding OAuth](https://support.google.com/cloud/answer/15549049?hl=en), [Google: publicul aplicației](https://support.google.com/cloud/answer/15549945?hl=en).
